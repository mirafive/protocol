# Agents working in mirafive/protocol

This repository is the wire contract of the MIRA FIVE SDKs. SDK repos copy its
`src/*.ts` files and its fixtures, so a change here is a change to every SDK.

## Commands

```sh
bun install --frozen-lockfile
bun run check       # everything CI runs: format:check, lint, typecheck, test, build
bun run format      # oxfmt (Markdown is not formatted)
bun run test        # vitest
```

## Rules

- PROTOCOL.md, FLAGS.md and API.md are the contract. Change their meaning only when
  asked; report gaps instead of filling them silently. The server (the MIRA FIVE
  Laravel app) is the reference for flags; FLAGS.md describes what it serves.
- `fixtures/flag-*.json`, `page-snippet.cases.json` and `reserved-names.json` are
  generated by the server's engine and copied byte-identical. Never edit them by hand;
  a new copy means new sha256 pins in `test/fixtures.test.ts`.
- `fixtures/batch-id.cases.json` is computed with Python `hashlib`, never with the
  TypeScript it tests.
- `src/` stays dependency-free and platform-neutral (no `node:` imports, no DOM beyond
  `URL`, `TextEncoder`, `crypto.subtle`). Every module must stay importable on its own;
  relative imports use the `.ts` extension so vendored copies keep working.
- Size is the headline goal: prefer the smaller correct code, no defensive layers.
- Comments only for a non-obvious constraint, one or two lines.
- A new module needs an entry in `tsdown.config.ts`, `package.json#exports`,
  `src/index.ts` and the README table.
- Do not run git write commands unless asked; the maintainer commits.

## Releasing

To release, bump `version` in `package.json`, add a `## X.Y.Z — YYYY-MM-DD` section to `CHANGELOG.md`, commit, then `git tag vX.Y.Z && git push origin vX.Y.Z`. `.github/workflows/release.yml` checks both, runs `bun run check` and creates the GitHub release. The package is private and never goes to npm.
